# 0004. Аккаунты не склеиваются по совпадающей почте

## Status

Accepted (2026-08-11)

## Context

С появлением входа по паролю у одного адреса могло оказаться два способа
попасть в аккаунт. Напрашивалось «умное» поведение: если почта совпала с уже
существующим OAuth-аккаунтом — привязать пароль к нему.

Раньше в VK-флоу такая склейка была: пользователь с совпадающим адресом
подшивался к VK-аккаунту. Вместе с паролями это превратилось в вектор захвата:
аккаунт с подтверждённой почтой на `@mail.ru` можно было перехватить входом
через VK-шлюз с суб-провайдером `mail_ru`.

Отдельная сложность — что считать признаком «этот аккаунт уже подтверждён».
Поле `emailVerified` для этого не годится: у всех OAuth-пользователей оно
остаётся `NULL` навсегда, потому что ни VK-флоу, ни `DrizzleAdapter` его не
проставляют. Проверка по нему позволила бы поставить свой пароль на чужой
OAuth-аккаунт.

## Decision

Автоматической склейки нет. Совпадение почты — понятный отказ с подсказкой,
каким способом входить.

Дискриминатор — **наличие строк в таблице `accounts`**, а не `emailVerified`.

| Что нашли по адресу | Поведение при регистрации паролем |
|---|---|
| есть строки в `accounts` (OAuth) | отказ: «уже привязана ко входу через Яндекс или VK» |
| подтверждённый password-аккаунт | отказ: «войдите или восстановите пароль» |
| брошенная неподтверждённая регистрация | пароль перезаписывается, уходит новое письмо |
| аккаунт вообще без способов входа (seed, dev-логин) | присваивается тому, кто подтвердит почту |

Склейка по e-mail удалена и из VK-флоу: там теперь ищут только по строке в
`accounts`, а занятый адрес даёт отказ. Уже склеенные ранее аккаунты не
затронуты.

## Consequences

**Положительные.** Закрыт вектор захвата чужого аккаунта через шлюз. Правило
одно и объяснимое: один способ входа — один аккаунт, пока человек сам не
свяжет их.

**Отрицательные и принятые.**

- VK не всегда отдаёт почту; тогда в `users.email` лежит заглушка
  `vk-<id>@vk.placeholder`. Если тот же человек потом зарегистрируется своей
  настоящей почтой, у него будет **два несвязанных аккаунта** с разными вещами
  и заявками.
- Объединить их сейчас нечем.

Правильное лечение — не слияние задним числом, а экран «Способы входа» в
профиле: задать пароль к OAuth-аккаунту, привязать провайдера, заменить
почту-заглушку на настоящую. Тогда второй аккаунт просто не появляется. Задача
отложена, см. [BACKLOG.md](../BACKLOG.md).

**Что это запрещает.** Возвращать автоматическую привязку по совпадению адреса
— в том числе «только для подтверждённых», потому что у OAuth-аккаунтов
признака подтверждения нет.
